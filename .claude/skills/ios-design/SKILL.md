# iOS 디자인 체크리스트 (필수)

이 앱의 모든 화면은 **iOS 앱처럼 보이고 동작해야 한다.** 사용자가 색·굵기·모서리·배치를 따로 지정하지 않은 세부 사항은 전부 이 문서를 기본값으로 쓴다. 확인 질문 없이 바로 적용하고, 끝나면 아래 "검증"까지 마친 뒤 보고한다.
세부 규칙과 이력은 `portfolio/DESIGN_GUIDELINES.md`(특히 2·3·4·9·11·13·18절)에 있다 — 충돌하면 그 문서가 우선.
**설계할 때(와이어프레임 포함)와 검증할 때 모두 "한 화면 중복 워딩 금지"(7절)를 기본으로 적용한다** — 새 문구를 쓰기 전에 그 정보가 이 화면에 이미 있는지 먼저 본다.

## 0. 기본 적용 규칙 — 사용자가 말하지 않아도 항상 (2026-10-09)
새 화면·탭·카드·폼을 만들거나 고칠 때 **설계 단계부터** 아래를 적용하고, 보고 전 8절 검증(`fit-audit`)을 통과시킨다.
1. **꽉 채움**: Galaxy Z Fold7 **펼침(750×832·750×700)·펼침+90도(832×750·832×620) — 실기기 캡처로 확정한 실제 폭(2026-10-10)** 에서 **가로·세로 스크롤 0 + 화면 아래 빈 공간 ≤ 20px(바깥 여백 포함)**. 남는 높이는 카드·행·차트가 나눠 쓴다 — 카드 안 행 균등 분배(`justify-content:space-between`), 입력·글자 크기 스케일(설계 `--sp`, 2단계 설계 `--ps`, 실측 이분 탐색), 차트는 남는 높이 전부, 목록형 카드는 `min-height`로 끝까지(빈 상태 문구는 가운데). 한 화면에 들어가면 `syncBodyScroll()`/`syncFitScroll()`로 스크롤을 잠가 터치 유격을 없앤다. **예외**는 내용이 본질적으로 긴 화면(세금 상식·매매전략 카드 목록·행이 많은 표)뿐 — 가로 스크롤 0만 지킨다. 접힘(390)은 가로 0만, 세로 스크롤 허용.
2. **입력 박스 통일**: 같은 화면의 `input`·`select`·읽기전용 박스는 **높이 하나(`--ctl-h`)**, 폭은 **sm(나이·월·짝 칸)/md(금액 칸)/lg(선택 칸) 3단계만**. 위아래 행의 입력 왼쪽 선이 수직으로, 같은 줄 박스의 top·height가 수평으로 맞아야 한다(임의 폭·높이, 칸마다 다른 padding 금지). 새 입력은 통일 레이어(retirement/index.html의 "입력 박스 통일 레이어")나 `.fm`(포트폴리오) 토큰만 쓴다.
3. **글자 절제·상태 표시·줄바꿈 균형**(상세 문구는 `keep-all`+`balance`, ` · ` 단위로만 끊음 — 4절): 행 옆 작은 안내 글자 금지 — 꼭 필요한 설명만 섹션 제목의 ⓘ(탭 풍선) 한 곳에. 숫자 칸의 기본값은 `0`이 아니라 **빈칸 + 연한 회색 placeholder**, 입력하면 진한 글자 + 연한 파랑 배경(기입 여부가 한눈에 보이게). 설정 결과 안내(🔗 연동 등)는 한 줄(`nowrap`+말줄임, 전체는 `title`).
4. **검증 필수**: `node .claude/skills/ios-design/fit-audit.js <retirement|portfolio --seed|home|signals|all> --boxes` 가 FAIL 0이어야 보고한다(8절). 이 규칙 때문에 사용자가 같은 말을 두 번 하게 만들지 않는다.

## 1. 색
- 포인트는 시스템 블루 `#007aff`(`--color-accent`) 하나. 새 포인트 색을 만들지 않는다.
- 배경은 그룹 회색 `#F2F2F7`(`--color-section-bg`), 그 위에 흰 카드(`--color-card`). 글자는 `--color-text` / `--color-secondary` / `--color-tertiary` 3단계만.
- 버튼은 **틴트 캡슐**: 파랑 12~14% 배경 + 파랑 글자(`.btn-green`), 회색 12%(`.btn-ghost`), 빨강 12%(`.btn-red`). 원색 배경 + 흰 글자 버튼(예: 빨강 "전체 해제")은 쓰지 않는다 — 켜짐/꺼짐이면 스위치로.
- 의미 색 축은 섞지 않는다: 한국식 상승/하락(`--color-up` 빨강/`--color-down` 파랑), 트리맵 손익(초록/빨강), 매수/매도(빨강/파랑), 카테고리 색(`ASSETTYPE_COLS` 등 iOS 시스템 컬러). 새 화면도 기존 축을 그대로 쓴다.
- 다크 모드: 하드코딩 색 대신 CSS 변수(`var(--color-…)`)를 쓴다. 헤어라인·그림자처럼 반투명이어야 하는 것만 `rgba()`.

## 2. 선·모서리·그림자
- 구분선/테두리는 헤어라인 0.5~1px `rgba(60,60,67,.08~.35)`. 진한 사각 테두리 금지.
- 모서리: 카드 `--radius`(16), 작은 요소 `--radius-sm`(10), 팝오버 12~14, 캡슐/알약 999.
- 그림자는 아주 옅게(카드 `0 1px 3px rgba(0,0,0,.04)`), 떠 있는 팝오버만 조금 진하게(`0 12px 32px rgba(0,0,0,.14)`).

## 3. 컨트롤
- 켜고 끄는 것 = **스위치 배너 `.tgl-banner`**(`role="switch"`, `aria-checked`, 안에 `<span class="sw">`). 켜지면 파랑 배경+흰 글자. 이름은 상태에 따라 바꾸지 않는다(예: "전체 보기" 고정).
- 여러 개 중 하나 고르기 = **세그먼트 `.period-tabs`**(회색 트랙 + 흰 선택 칩).
- 여러 개 켜고 끄기 = **알약 `.toggle-pill`**(색 점 + 이름), 목록이 길면 팝오버 안에.
- **풀다운(select)은 `shared/ios-select.js`가 자동으로 iOS 메뉴(둥근 팝오버, 접힘은 시트)로 바꾼다** — 새 select는 그냥 `<select>`로 쓰고, 고정 `height`를 주면 위아래 padding 0 + `line-height`=높이(글자 아랫부분 잘림 방지). 열린 목록을 CSS로 꾸미려 하지 말 것.
- **수동 입력·추가 폼은 접이식(`<details>`) 대신 토글 배너**를 필터 줄/카드 상단 오른쪽 끝에 둔다(펼침·90도 한 줄). 점검용 창(예: 전략 매칭)은 자주 쓰는 줄에 두지 말고 백업/복원 같은 관리 창에.
- 부가 정보·선택 목록은 **팝오버/시트**(absolute, 그래프·본문을 밀어내지 않음, 바깥 탭·ESC로 닫힘)를 우선한다. 화면을 상시 차지하는 패널은 지양.
- 눌림 피드백은 `shared/icons.js`가 자동으로 준다(0.95배 + 밝기). 선택 상태가 바뀌는 컨트롤은 `PRESS_SKIP`에 넣는다.

- **알림창은 `shared/dialog.js`**: `alert/confirm` 대신 `await iosConfirm({..., destructive})`/`iosAlert()`, 입력 누락은 `fieldError(input,msg)`. 매수=빨강·매도=파랑 틴트, 확인 모달은 `setConfirmTone()`. (세부: DESIGN_GUIDELINES 15절)

- **입력 폼은 `.fm` 시스템**(DESIGN_GUIDELINES 16절): 12칸 grid·36px 입력·우측 액션 행, 헬퍼 `fmField/fmSelect/fmClassFields`. 행 연필·휴지통은 `iconBtn()`(= 매매 이력 `.tl-icon`)만 쓴다.

## 4. 아이콘·글자
- **이모지 금지** — `shared/icons.js`의 SF Symbols식 라인 SVG(`currentColor`, 1.15em). 새 아이콘은 그 파일 `MAP`/`SYMBOLS`에 추가.
- 글꼴 Pretendard. 크기 위계: 라벨 10~11px/600, 본문 12~14px, 강조 수치 13~17px/700~800. 한 화면에서 위계를 3단계 이상 늘리지 않는다.
- 글자가 넘치면 말줄임(…) 또는 두 줄 — 잘리거나 겹치면 안 된다. 수치(%, 금액)는 말줄임 대상이 아니다.
- **줄바꿈 균형(지시 없어도 항상)**: 카드·배너 상세 문구가 줄바꿈되면 `word-break:keep-all` + `text-wrap:balance`로 두 줄 길이를 맞추고, ` · `로 이어진 구절 단위(`.nw`=nowrap 조각)에서만 끊는다. 낱말 중간 끊김·한 글자만 홀로 남는 줄 금지. 라벨·단위·수치는 줄바꿈 말고 `nowrap`. (DESIGN_GUIDELINES 22절)

## 5. 레이아웃 (Galaxy Z Fold7 3상태)
> **검증 폭은 실기기 기준**: Fold7 안쪽 화면 1968×2184px ÷ 밀도 2.625 → 펼침 기본 ≈ 750px, 펼침+90도 ≈ 832px(사용자 캡처로 확인). 904/1003px로만 검증하면 실기기에서 3카드가 세로로 쌓이거나 칸이 잘린다. 폭 breakpoint는 700px 기준(≥700 = 가로 다열).

| 상태 | 검증 뷰포트 | 규칙 |
|---|---|---|
| 접힘 | 390×800 | 세로 스크롤 허용, 가로 스크롤 금지 |
| 펼침 | 750×832, 750×700 (옛 904×900·904×780은 `--extra`) | **결과·대시보드 화면은 세로 스크롤 없이 한 화면**, 배너 줄은 한 줄 |
| 펼침+90도 | 832×750, 832×620 (옛 1003×810·1003×700은 `--extra`) | 위와 동일 |
- **꽉 채움이 기본(0절)**: 고정 px보다 `flex`/`grid`/`%`. 높이가 남으면 핵심 콘텐츠(그래프·트리맵·표·입력 카드)가 차지하게 하고 빈 여백을 남기지 않는다(하단 빈 공간 ≤ 20px). 중복 정보는 지운다.
- **빈 여백 때문에 생기는 스크롤 금지**: 스크롤 컨테이너(`getScroller()`)는 넘친 양이 자기 `padding-bottom` 이하이면 `syncFitScroll()`이 스크롤을 끈다(ResizeObserver로 자동). 새 화면은 이 구조(`.page`/`.subpage`) 안에 두면 자동 적용된다 — 따로 `overflow`를 걸어 우회하지 말 것.
- 남는 높이 계산은 `getScroller()` 기준 콘텐츠 좌표(`rect.top - scroller.top + scrollTop`)로. 뷰포트 좌표만 쓰면 스크롤된 채 다시 그릴 때 커진다.
- 한 줄 배너는 `nowrap` + 실측 압축(`fitChartTopRow()` 방식: 넘치면 여백→글자 순으로 줄이고, 최후에만 줄바꿈).
- **터치 유격 금지(현금흐름 방식)**: 한 화면에 들어가는 화면은 `syncBodyScroll()`로 스크롤을 잠그고 `overscroll-behavior-y:none`을 둔다. 남는 높이는 `--sp`/`--ps` 스케일(실측 이분 탐색)로 쓴다(DESIGN_GUIDELINES 20절).

## 6. 차트·캔버스
- DPR 대응, 박스는 둥근 헤어라인 + `#FAFAFC` 바탕, 격자는 아주 옅게, 축 글자 `#8e8e93` 10px.
- 라벨은 **절대 겹치지 않게**: 가용 높이에 맞춰 글자·간격을 줄이고(`planLineLabels`), 띠 안에서 단조 배치(`placeLabelsInBand`). 차트를 키워서(스크롤 유발) 해결하지 않는다.
- 검증용으로 레이아웃 결과를 캔버스에 붙여 둔다(예: `cv._labelLayout.overlaps`).

## 7. 한 화면 중복 워딩 금지 (설계 기본값, 2026-10-05)
**한 정보는 한 화면에 한 번만.** 화면·카드·폼·팝업을 만들 때 아래를 먼저 지키고, 8절 검증으로 확인한다. (세부는 DESIGN_GUIDELINES 18절)
- **이름은 한 곳**: 종목·계좌 이름이 바/행에 이미 있으면 그 아래 카드·폼·차트 제목에 다시 쓰지 않는다. 헤더 띠와 본문이 같은 이름을 각각 쓰는 구조도 금지 — 이름은 hero(또는 맨 위 바) 한 곳.
- **모드는 한 곳**: 세그먼트·스위치가 보여주는 모드를 라벨·배지·버튼 글자에 다시 쓰지 않는다(예: 라벨 "금액" 고정, 버튼 "확인", `매도 전략` 배지는 [매수|매도] 세그먼트와 중복).
- **선택된 탭/서브탭/버튼 이름을 제목으로 다시 쓰지 않는다**(탭 "수익률 민감도" → 패널 제목 "수익률 민감도 — …" 금지). 제목이 필요하면 부가 정보("월별", "2026년")만.
- **같은 수치·같은 설명 문장은 한 칸**: 배지의 낙폭 %를 가격 줄·의견 박스에 또 쓰지 않는다. 팝업이 뒤 화면 수치를 그대로 반복하지 않는다.
- 확인창: 제목(무엇) + 대상 값 + 동사 버튼. "…할까요?" 질문줄·"삭제 확인" 버튼으로 같은 말을 세 번 하지 않는다.
- 하나의 카드로 읽혀야 하는 영역은 안쪽에 또 카드를 만들지 않는다(헤어라인으로만 나눔). 폭이 다른 카드·헤더가 겹쳐 "따로 노는" 느낌이 나면 구조를 합친다.
- **표·목록 열 간격**: 값 열이 남는 폭을 나눠 가져 100px씩 벌어지면 "첫 열이 남는 폭, 값 열은 내용 폭"(매매이력 `tl-table`·`.tbl-cap`)으로 모은다. 그 열을 덮는 `!important` 잔재를 확인할 것.

## 8. 검증 (보고 전 필수) — 수정 크기에 맞춰 단계화 (2026-10-10, 토큰 효율)
**목적은 토큰 사용 효율화** — 부분 검증이 기본값이고 풀 검증은 필요할 때만 쓴다. 같은 화면 스크린샷 반복·불필요한 서브에이전트·파일 통째 읽기·전 탭 재측정을 피하고, 한 번에 여러 뷰포트를 한 스크립트로 재서 결과 숫자만 읽는다.
**사용자가 말하지 않아도 Claude가 스스로 판단한다 — 묻지 않는다.** 코딩 전에 변경 범위를 보고 수준을 정하고, 보고에 한 줄로 적는다("작은 수정 → 부분 검증" / "큰 수정 → 풀 검증, 이유 한 마디").

**판단표** (아래 "큰 수정 신호"가 하나라도 있으면 큰 수정):
| 큰 수정 신호 | 작은 수정(해당 없음) |
|---|---|
| 탭·카드·행의 **구조(마크업·그리드·flex 방향) 변경**, 새 화면·컴포넌트·보기, 보기 통합/삭제 | 문구·색·글자 크기 한두 곳, 한 칸 폭·간격·정렬 미세 조정 |

**승격 규칙**: 작은 수정으로 시작했어도 ① 실측에서 다른 화면·뷰포트의 넘침/겹침이 나오거나 ② 고치다 공통 규칙을 건드리게 되면 즉시 큰 수정으로 올려 풀 검증한다. 판단이 애매하면 큰 수정으로 본다. 반대로 작은 수정에 풀 검증을 돌리지 않는다(토큰 낭비).
- **작은 수정(부분 검증)**: 바뀐 화면만 **펼침 750×700·펼침+90도 832×620 두 뷰포트** 실측(가로·세로 넘침, `fit-audit` 모듈의 `measureFit/measureBoxes`로 겹침·두 줄·잘림 0) + 스크린샷 1~2장. dup-check·`fit-audit all`·배포본 재확인은 생략.
- **큰 수정(풀 검증)**: 아래 1~6 — 4개 뷰포트 × 영향받는 모든 탭, dup-check, `fit-audit <preset> --boxes`, (push했다면) 배포본 재확인.

### 풀 검증 절차
1. `npx --yes serve -l 4173 .` + npx 캐시 playwright(`NODE_PATH`)로 위 뷰포트를 띄운다. 폰트 CDN(cdn.jsdelivr.net)은 막지 말 것(글꼴 폭이 달라짐). **4173이 이미 쓰이면 serve가 다른 포트로 올라간다 — 로그의 포트를 확인할 것.**
2. 수치로 확인: 가로 `scrollWidth - clientWidth === 0`, 한 화면 대상은 스크롤러에 `.fit-noscroll`·휠 후 `scrollTop === 0`, 배너 줄 높이(한 줄), 라벨 겹침 0.
3. **중복 문구 검사**: 화면 상태마다 `.claude/skills/ios-design/dup-check.js`(`await require(...).run(page, {names:['이 화면의 종목명', ...], frame})`)로 exact(같은 문구 2회↑)·token(낱말 3회↑)·names(이름 2회↑)를 센다. 수정 전(`git archive HEAD`를 다른 포트로 서빙)·후 건수를 같이 보고하고, 남은 항목은 "데이터 값의 정상 반복(일반계좌×4 등)·오버레이 뒤 화면·의도적 구조 중복"인지 사람이 판정해 이유를 적는다.
4. **꽉 채움·입력 박스·겹침 검사(풀 검증 필수)**: `node .claude/skills/ios-design/fit-audit.js <preset> --boxes [--seed] [--extra]`(preset: retirement·portfolio·home·signals·all, 기본 base `http://localhost:4173/`, `--base`로 배포 URL 지정). 4개 뷰포트 × 모든 탭·서브탭에서 세로·가로 넘침, 하단 빈 공간, 휠 후 scrollTop, 같은 줄 박스 높이 차, 높이·폭 종류, 어긋난 왼쪽 선을 표로 보고 FAIL을 모두 고친다. 포트폴리오는 `--seed`(가상 종목 25개)로 목록이 실제 길이일 때도 본다. 예외 화면은 스크립트의 `LONG` 목록에 이유와 함께 추가.
5. 스크린샷을 직접 본다(정렬·쏠림·색 조합).
6. 커밋 → (요청 시) push → 배포본 재확인(`--base` 배포 URL로 fit-audit 재실행).
