# 포트폴리오 · 은퇴 현금흐름 대시보드

자산 포트폴리오 대시보드와 은퇴 후 현금흐름 시뮬레이션을 하나로 통합한 정적 웹사이트입니다.
빌드 도구 없이 순수 HTML/JS로 동작하며, 모든 데이터는 브라우저 `localStorage`에만 저장됩니다.

- 📊 [자산 포트폴리오](./portfolio/) — 이전: [-New-portfolio-dashboard](https://withgest-lab.github.io/-New-portfolio-dashboard/)
- 🧮 [은퇴 후 현금흐름](./retirement/) — 이전: [Retirement-dashboard-](https://withgest-lab.github.io/Retirement-dashboard-/)
- 📈 [KIS 기반 매수·매도 전략](./signals/) — 화면은 이 저장소, **데이터**(scores.json·detail)는 [kis-buy-signal](https://github.com/withgest-lab/kis-buy-signal)(별도 저장소, 매일 GitHub 서버에서 계산)
- 🛟 운영·복구 안내: [RECOVERY.md](./RECOVERY.md)

## 구조

```
/
├── index.html         # 랜딩 페이지 (세 대시보드로 이동)
├── portfolio/
│   └── index.html     # 자산 포트폴리오 대시보드
├── retirement/
│   └── index.html     # 은퇴 후 현금흐름 시뮬레이션
├── signals/            # KIS 기반 매수·매도 전략 화면
│   └── index.html       # 화면은 이 저장소 소유. scores.json·detail/*.json 은 커밋하지 않고
│                          배포 때 deploy.yml이 kis-buy-signal 저장소 data 브랜치에서 받아 채운다
│                          (무결성 점검 통과 시에만 배포, signals/_source.json에 출처 기록).
└── shared/
    ├── bridge.js       # 포트폴리오 잔액 → 은퇴 계좌 잔액 집계 (localStorage 읽기 전용)
    └── ios-select.js   # 모든 화면 공통 iOS 풀다운
```

## 포트폴리오 ↔ 은퇴 연동 방식

1. 포트폴리오에서 개인연금(`pension_personal`) 자산을 추가/수정할 때 **세부계좌(농협/미래에셋)**를 지정할 수 있습니다.
2. 은퇴 대시보드의 각 계좌 섹션(농협·미래에셋 연금저축, IRP, 퇴직연금, ISA)에 있는
   **"🔗 포트폴리오 값으로 채우기"** 버튼을 누르면, `shared/bridge.js`가 포트폴리오의
   `pf_assets_v1` 데이터를 읽어 계좌별 잔액(KRW 환산, 만원 단위)을 계산해 채워줍니다.
3. 버튼을 누르는 행위 자체를 "지금 값으로 덮어써라"는 명시적 의사로 간주해, 잠금 상태와 무관하게
   해당 계좌 잔액을 항상 포트폴리오 값으로 덮어씁니다.
4. 개인연금 자산 중 세부계좌가 지정되지 않은 항목은 농협/미래에셋 어느 쪽에도 합산되지 않고,
   버튼 클릭 시 별도 경고 메시지로 안내됩니다.

국민연금 수령액, 계좌별 예상 수익률, 물가상승률, 월 생활비, 비공제원금 등 포트폴리오에
존재하지 않는 개념은 계속 은퇴 대시보드에서 수동으로 입력합니다.

## 은퇴 현금흐름 대시보드가 하는 일

단순 자산 합계 계산기가 아니라, **6개 계좌(농협·미래에셋 연금저축, 개인IRP, 퇴직연금(DC→퇴직IRP),
국민연금, ISA)를 동시에 놓고 세금·건강보험료를 줄이면서 기대수명까지 생활비를 대는 인출 순서·시점·금액을
설계**하는 것이 목적입니다. "자동설계" 버튼을 누르면 전 계좌의 수령 시작 나이·월 수령액을 한 번에 계산합니다.
계산 규칙·가정·출처는 [`retirement/CALC_SOURCES.md`](./retirement/CALC_SOURCES.md)에 정리돼 있습니다.

- **계산은 한 곳**: 모든 계산은 `retirement/calc.js`(DOM과 무관한 순수 함수, `npm test` 50개 테스트)에 있고,
  자동설계 근거·요약(팝업과 요약 탭)·차트·지표는 모두 `simulate()` 결과 하나만 읽습니다(같은 돈을 화면마다 따로 합산하지 않음).
- **생활비 판정은 세후·오늘 돈 가치**: 지표 카드·배너의 공백기/완성기 월평균과 여유/부족은 세금과 건보료
  (은퇴 후 지역가입자, 피부양자 가족 설정에 따름)를 뺀 금액을 오늘 돈 가치로 환산해 월 생활비와 비교합니다. 차트 막대는 그해 실제로 받는 세전 금액,
  세후 합계는 선으로 함께 그립니다.
- **법정 인출순서**: 연금계좌는 과세제외금액(세액공제 안 받은 원금·안세공) → 이연퇴직소득 → 세액공제분·운용수익
  순으로 빠지는 것으로 계산합니다. 안세공은 원금만 비과세이고, 2027년부터는 세액공제 한도 초과 납입분이 자동으로 더해집니다.
- **자동설계 = 생활비 평탄화**: 각 계좌 인출액은 정한 구간 끝에 잔액이 정확히 0이 되도록 물가상승률을 반영해
  역산합니다(Growing Annuity). 퇴직IRP 개시 나이·ISA·미래에셋 소진 나이는 "해마다 세후 소득 중 가장 적은 해"가
  가장 크도록 고르고, 비슷하면 생애 세금+건보료가 적은 쪽을 고릅니다.

계좌별 입력 카드(ISA·사적연금·퇴직연금·국민연금)는 갤럭시 Z Fold 7 펼침 화면 기준으로 한 줄에
5개 카드가 들어가도록 압축돼 있고, 카드 머리는 계좌 색 틴트로 구분합니다(사적연금 3계좌는 초록→민트→시안 계열).

### 검증한 세금·건보료 규정 (2026년 기준, 출처는 CALC_SOURCES.md)

| 항목 | 반영 내용 |
|---|---|
| 사적연금 과세 | 연금저축·IRP 세액공제분·운용수익(+퇴직IRP 운용수익)이 연 1,500만원 이하면 5.5%(70세 미만)·4.4%(70~79세)·3.3%(80세+), 넘으면 16.5% 분리과세와 종합과세 중 적은 쪽(1,500만원은 인출 상한이 아니라 세율 경계) |
| 국민연금 | '내 연금' 예상액(현재가치)을 매년 물가만큼 증액, 조기 −6%/연기 +7.2%, 공적연금 종합과세(연금소득공제·본인공제·표준세액공제·지방세) 추정 |
| 연금수령한도 | 1~10년차 연초 평가액÷(11−연차)×120% 초과분은 연금외수령(16.5% 기타소득, 이연퇴직소득은 감면 없는 퇴직소득세) |
| 퇴직소득세 | DC 퇴직 시 평가액(운용수익 포함) 기준 국세청 공식(공개 예시 1억·10년 = 387.5만원 일치), 지방세 10% 별도, 연금수령 시 실제 수령연차 1~10년 30%·11~20년 40%·21년+ 50% 감면 |
| ISA | 계속 보유 시 총 납입한도 1억원, 해지 시 전 기간 순이익에서 200만원 비과세 후 9.9% |
| 연금 수령 최저 연령 | 연금저축·IRP(퇴직IRP 포함)는 만 55세부터 연금 수령 — 55세 전 은퇴면 은퇴~54세는 ISA·비과세 원금 가교 인출 |
| 건강보험 피부양자 | 공적연금+사업·근로·이자·배당·기타소득 합산(사적연금·ISA 제외), 국민연금은 개시 시점 명목 금액으로 판정, 재산 5.4억/9억 기준, 사업소득 500만원 초과 탈락(사업자등록 시 1원이라도 탈락) |
| 지역가입자 건보료 | 소득월액×7.19%(최저보험료는 소득분에만) + 재산점수×211.5원(1억 공제 후 0이면 0원), 상한 4,591,740원, 장기요양 13.14% |

### 알려진 한계

- 국민연금 정상수급나이는 출생연도별로 다르지만(61~65세) 65세로 단순화했습니다.
- 국민연금 소득세는 2002년 이전 납입분 비과세를 반영하지 않아 보수적으로(많게) 나옵니다. 배우자 공제 등 개인별 공제도 반영하지 않습니다.
- 연금수령한도의 연차는 연금저축·IRP를 55세 1년차로 가정합니다(2013.3 이전 가입 계좌의 6년차 기산 특례 미반영).
- 은퇴 후 근로·사업소득에 따른 국민연금 재직자 감액은 반영하지 않습니다. 건보료는 2026 요율·현재 재산으로 고정하고, 1년 시차·임의계속가입은 반영하지 않습니다.
- 자동설계의 평탄화는 계좌별 인출 "구간"만 고르는 방식이라 완전히 평평하지는 않습니다.
- 무주택자의 전월세 재산 인정액은 사용자가 환산한 값을 직접 입력합니다(월세→보증금 세부 환산 계수 원문 미확보).
- 지역가입자 요율·세율 구간·피부양자 기준선은 2026년 기준 명목 고정이며, 매년 개정될 수 있습니다.

## KIS 기반 매수·매도 전략 대시보드 & 배포 방식

`signals/`는 별도 저장소([withgest-lab/kis-buy-signal](https://github.com/withgest-lab/kis-buy-signal))의
Python 파이프라인(KIS Open API 시세 수집 → MDD/RSI/MFI 스코어링 → 텔레그램 알림)이 매일
발행하는 `index.html`/`scores.json`/`detail/*.json`을 그대로 보여주는 읽기 전용 화면입니다.

- 이 저장소는 그 파이프라인의 API 키·텔레그램 토큰을 전혀 갖고 있지 않습니다. 두 저장소는
  완전히 독립적으로 운영됩니다.
- GitHub Pages 배포 방식이 "브랜치에서 배포"에서 "GitHub Actions로 배포"로 바뀌었습니다
  (`.github/workflows/deploy.yml`). 이 워크플로는 push/스케줄(매일 KST 08:00경)/수동 실행 시
  `portfolio/`·`retirement/`·`shared/`는 그대로 복사하고, `kis-buy-signal`의 공개 Pages에서
  최신 `index.html`/`scores.json`/`detail/*.json`을 새로 받아와 `signals/`를 채운 뒤 하나로
  묶어 배포합니다.
- 데이터/화면 fetch가 실패하면(원본 사이트 장애 등) 배포 자체가 실패 처리되어 직전까지 정상
  배포돼 있던 사이트가 그대로 유지됩니다(부분/깨진 배포 없음).
- **유지보수**: KIS 기반 매수·매도 전략 대시보드의 화면·로직·알림을 고치려면 `kis-buy-signal` 저장소만
  고치고 그 저장소의 `main`에 push하면 됩니다. 이 저장소(portfolio-retirement-dashboard)에서
  손으로 옮기거나 동기화해야 할 파일은 전혀 없습니다 — 다음 배포(매일 자동, 또는 수동
  `workflow_dispatch`) 때 최신 내용이 자동으로 반영됩니다.

## 보안 메모

- 이 저장소 자체는 신규 백엔드/서버·시크릿이 없습니다 — 포트폴리오/은퇴 대시보드는 정적 파일 +
  브라우저 `localStorage`만 사용합니다.
- `shared/bridge.js`는 외부 요청을 전혀 하지 않고, `localStorage`를 읽어 집계만 수행합니다.
- 시세 조회(포트폴리오)는 야후 파이낸스/네이버 API를 CORS 프록시로 호출하며, 이때 전송되는 값은
  티커 심볼뿐이고 계좌 잔액·개인 재무 정보는 전송되지 않습니다.
- 실제 자산·잔액 데이터는 코드/커밋에 포함되지 않고, 각 사용자의 브라우저 `localStorage`에만 남습니다.
- 이 저장소의 CI(`deploy.yml`)에는 시크릿이 전혀 없고 외부에서 받은 코드를 실행하지도
  않습니다. 다만 배포마다 다른 공개 저장소(kis-buy-signal)의 게시된 정적 파일을 읽어오는
  네트워크 의존성이 하나 추가되었습니다 — 그 사이트가 일시적으로 응답하지 않아도 배포가
  실패할 뿐, 사이트가 깨진 상태로 게시되지는 않습니다.

## 로컬 실행

```
npx serve .
```

또는 VS Code의 Live Server 확장 등으로 정적 서버를 띄운 뒤 `index.html`을 엽니다.
`file://`로 직접 열면 일부 브라우저에서 `localStorage`/모듈 로드가 제한될 수 있습니다.
